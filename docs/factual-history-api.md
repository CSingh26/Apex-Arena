# Cursor-bound factual history (web and native clients)

Bootstrap, state, timing and SSE contain compact current observations, not the full retained lap/control history. Driver `completed_lap` and `tyre_age_laps` describe that driver's completed lap; null means unknown. Never substitute the leader's lap or `leader_lap - lap_start`. `tyre_age_basis` and bounded evidence accompany known ages. Pace and observed pit-cycle loss are descriptive, low-confidence evidence summaries, not tyre-life or optimal-strategy predictions.

Read-only backend routes:

- `GET /api/v1/sessions/{session_key}/intelligence-detail?driver=4&driver=16&family=laps&family=control&cursor=1234`
- `GET /api/v1/race-rooms/{slug}/intelligence-detail?driver=4&family=laps`

The first-party same-origin proxy uses `/sessions/...` and `/rooms/...`; helpers are `getSessionHistoryDetail` and `getRoomHistoryDetail`. Native clients use the backend paths. No replay operator credential is needed for these public reads. Both requests are subject to the shared read budget. Pass an AbortSignal when a view/selection is replaced; do not launch a new detail request for every telemetry sample.

Select one or two distinct driver numbers and one or more distinct families from `laps`, `stints`, `pits`, `weather`, `control`. The session cursor is optional and cannot exceed acknowledged projection progress. Room requests capture the room's current view; callers cannot override its cursor. Unknown room/session returns404, invalid selection422, changed room view409 (refresh compact state and retry), and temporary admission/storage failure503 with Retry-After1. Existing429/503 client backoff applies. A deterministic bounded/legacy/history failure returns200 with `availability: unavailable` and a reason, never a newer replacement dataset.

Available/partial responses include `session_key`, `view_sequence` (C), `history_sequence` (H), canonical `analysis_time`, `projection_status`, and immutable `history_reference` (algorithm/schema, base source B/id/checksum, H/id). B≤H≤C. These are factual-history checkpoints, not detector/cooldown restart checkpoints. Algorithm identity is persisted, supplied by the active backend, and must match on reads. Missing old details remain explicitly unverified; there is no automatic legacy adoption.

The response's `data.drivers` includes only selected retained drivers/families. `truncation` and `unresolved_deletions` describe the full bounded projection, not merely the selected slice. Weather/control are session-wide when requested. Unselected driver corrections still affect global retention/authority. No selected driver's absence proves they did not participate. Public current best is partial/unknown if retained history cannot certify the all-session minimum; exact deletions retract addressed retained laps and phase bests.

Lap interval fields include start/end, authority, evidence and limitations. OpenF1 `date_start` is approximate. A complete duration can support an approximate end; received time, sector samples and the leader lap cannot. Null intervals and unknown control classification are valid. Control/deletion corrections are applied in durable append order at C; no future facts are borrowed. `analysis_time` is the maximum accepted source event time through C, separate from a replay display clock. Derived events do not advance it.

Current completed-lap payloads are reconstructed from that one retained completed identity; newer incomplete observations remain in detail rather than being relabeled as the completed lap. Current stint/compound and age evidence refer to the same latest retained stint, even after an older-stint correction. Qualifying `best_laps`, `best_laps_by_phase` and `session_best` use the same retraction/uncertainty authority, with `best_lap_availability` (`unknown`, `available`, `partial`). Retraction changes the current projection and later comparison baseline, never previously recorded derived rows. Lap-carried Q/SQ metadata may initialize or advance within its session family; explicit normalized phase events remain authoritative corrections.

Room responses also identify room id, mode and discussion generation. Replay delivery rereads that tuple and playback cursor, including same-generation seeks. LIVE uses acknowledged session C, not its usually-zero replay cursor; forward live progress can leave a truthful older returned C. Cache hits undergo the same room fence. This is a final-read consistency check, not a lock held over network delivery or an ABA transition counter. Consumers must still discard a response after their own local view changes.

## Operating ceilings

- Private retained context:64drivers,120laps/24stints/24pits per driver,60weather/120control records. Current public state is detached; details/cache hits are detached too.
- Detail checkpoints: first relevant source, every64 relevant sources or2048 normalized positions since the last encoding attempt, plus dirty explicit terminal. Immutable8MiB maximum; unchanged raw ticks reuse the reference/blob. Compact snapshot input≤2MiB, no snapshot later than requested C.
- Reader:64row pages,2048 total normalized positions/rows across B→H plus snapshot→C,128 relevant transforms,64KiB/source payload and8MiB aggregate source payload;512KiB response. Full transform precedes selection filtering.
- Two active reconstruction tasks/process, no queue; at most4coalesced callers/key and8total. Deadline2s including encoding, individual SQL≤500ms. Cancellation cleanup≤250ms; slots remain owned until actual work exits.
- Actual HTTP disconnect detaches that request's waiter; a coalesced peer can continue. Final-waiter disconnect cancels shared work. Container shutdown closes admission and cancels tracked readers before disposing dependencies, waits at most250ms and never releases a still-running slot early. Cancellation-resistant work may outlive that bounded wait; admission remains closed and its eventual result cannot repopulate the cache.
- Cache:32 immutable encoded selected results,8MiB accounted total,≤512KiB/entry,TTL60s; exact revision/selection/algorithm/view-fence key. This is not a browser/global service cache guarantee.
- Large live private contexts:4 pinned critical and2 pinned replay contexts, idle-only coordinated eviction. Re-entry reconstructs effects-off; public/SQL snapshots are not deleted. Full detector restart still consumes the durable source prefix.

MQTT admission is bounded before loop scheduling:256messages/8MiB including in-flight,64KiB/message, one tracked dispatcher. Batches share the default1500ms ordering wait. Internal context pressure retries the same payload4times with0.1/0.25/0.5s waits. REST retries its same fetched batch and advances cursors/seen only on success. Sticky `dispatch_*` gap counters remain separate from connection health after overflow/exhaustion/shutdown. No broker redelivery or lossless overload guarantee is made; REST repair only covers its actual endpoint/window behavior.

Checkpoint envelopes use the explicitly versioned `interned_facts_v1` representation: complete exact evidence values are interned, not merged by UUID alone. The public detail schema is unchanged. The codec permits at most57,116 references and750,000 scalar/container nodes (depth32), derived from the retained model, and verifies checksums before decode.

If a valid retained context still exceeds8MiB, `history_detail_status: checkpoint_bytes` is committed with factual progress and compact state. Source acknowledgement continues. An old immutable B may remain as identity, but the reader returns unavailable, never old rows labeled current; an initial oversized revision has no B. H/C stay truthful. Encoding is retried only after64additional relevant facts/2048positions or a dirty explicit terminal. Effects-off restart reconstructs the same cadence/status; a later successful checkpoint clears it atomically. Checksum/identity conflicts do not take this degradation path. Ordinary populated details and extreme unavailable cases are measured separately.

Limits are operating ceilings, not production latency/RSS claims. The ignored implementation report records synthetic local SQL/publication and populated-reader measurements. Broader strategy integration, final semantic-version coordination and production readiness remain separate work.
